# Candidate360 Design

## 目标

Candidate360 将候选人分散在简历中心、人才库、消息中心、匹配分析和话术草稿中的信息聚合到一个页面，方便本地 Web Console 查看候选人的完整上下文。

## 数据来源

不新增表，不修改 `schema.sql`。所有信息从现有表读取：

- `candidates`：候选人基础信息、技能、简历文本、raw_data
- `match_scores`：候选人匹配分
- `conversations` / `messages`：沟通记录
- `logs`：匹配分析、话术草稿、人才库状态事件、时间线

缺失数据统一显示“暂无数据”，页面不因空数据崩溃。

## 聚合内容

- 基础信息：姓名、城市、来源、状态、创建时间、更新时间
- 简历信息：教育、工作经历、项目经历、技能、简历评分、AI总结
- 匹配分析：匹配度、等级、优势、风险、建议动作、标签、最近分析时间
- 沟通记录：消息数量、最近消息、最近回复时间、会话状态
- 话术草稿：草稿数量、最近草稿、草稿状态
- 人才库阶段：从 `talent_pool` 的 logs 事件源读取最新状态
- AI建议：本步骤使用规则型 Mock 建议，后续可接入 DeepSeek

## 页面入口

- `/candidate360/{candidate_id}`
- `Talent Pool` 候选人详情页增加“查看360画像”
- `Candidates` 列表增加“查看360画像”

## 安全边界

Candidate360 只读聚合数据，不触发 Boss，不发送消息，不投递，不展示 API Key 或 `.env`。
