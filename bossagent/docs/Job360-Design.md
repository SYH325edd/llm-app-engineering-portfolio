# Job360 Design

## 目标

Job360 将岗位池、匹配分、候选人情况、沟通情况和 logs 中的匹配分析聚合到一个岗位全景页面，用于判断一个岗位是否应继续搜索、暂停搜索或优化 JD。

## 数据来源

不新增表，不修改 `schema.sql`。所有信息从现有表读取：

- `jobs`：岗位基础信息
- `match_scores`：岗位匹配分、候选人匹配统计
- `conversations` / `messages`：岗位相关沟通统计
- `logs`：岗位匹配分析、人才库状态事件、时间线

缺失数据统一显示“暂无数据”或 `0`，页面不因空数据崩溃。

## 聚合内容

- 岗位基础信息：标题、公司、城市、薪资、来源、创建时间
- 岗位分析：匹配度、等级、标签、分析摘要
- 候选人情况：匹配候选人数、A级、B级、C级
- 沟通情况：已发送消息人数、已回复人数、面试人数、Offer人数
- AI建议：本步骤使用规则型 Mock 建议，后续可接入 DeepSeek

## 页面入口

- `/job360/{job_id}`
- `Jobs` 岗位池增加“查看360画像”

## 安全边界

Job360 只读聚合数据，不触发 Boss，不发送消息，不投递，不展示 API Key 或 `.env`。
