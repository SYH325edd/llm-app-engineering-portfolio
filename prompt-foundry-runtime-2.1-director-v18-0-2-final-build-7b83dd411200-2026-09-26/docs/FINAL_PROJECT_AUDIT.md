# Prompt Foundry Runtime 2.1 最终独立项目审计

## 1. 审计范围

本报告独立审查以下层级：

- Prompt Foundry v1.3 Frozen Core（冻结核心）及其哈希保护边界。
- Runtime 2.1（运行时）单元化、检查点、恢复与重试。
- Story Bible / Scene Plan / Script / Storyboard / PVB / PSB / Style / Director / State+ShotSpec（各生产阶段）。
- Consumption Compiler v1（消费编译器 v1）与 Semantic Lint（语义检查）。
- Character / Scene / Shot Prompt（人物 / 场景 / 分镜提示词）。
- Web（网页）信息架构与汉化。
- 本地配置、密钥与数据文件边界。
- 自动化测试与真实保存 Run（运行记录）`run_75ba9d49f638` 的 51 镜重新编译。

## 2. 总体结论

项目上游生产链已经具备稳定的阶段契约、检查点恢复、结构校验和 Frozen Core（冻结核心）保护。本轮真正完成的是此前缺失的“最后消费边界”：不再把 State / Director / ShotSpec（状态 / 导演 / 镜头规格）的内部表示直接序列化给生成模型，而是在 Runtime（运行时）外层新增消费编译与语义拒绝机制。

新版并没有掩盖上游问题。相反，真实 51 镜重新编译暴露了原来会直接进入最终 Prompt（提示词）的跨镜动作和道具绑定错误。

## 3. 本轮已完成

### Web（网页）

- 用户可见静态文案汉化。
- `pending / running / completed / failed_recoverable` 等内部状态转换为中文人话状态。
- 主导航只保留：总览、生产进度、剧本、人物提示词、场景提示词、分镜提示词。
- 生产设计、导演与状态、校验与日志进入默认折叠的“高级调试区”。
- 关闭高级调试区时若当前处于调试标签，自动返回总览，避免调试内容残留主区。
- 单镜 `blocked`（阻断）时禁用复制按钮，并显示具体错误码与中文说明。
- Asset Warning（资产警告）显示在提示词正文之外，不污染复制内容。

### 人物提示词

- 区分人物锁定、基础服装、稳定外层服装、阶段服装、视觉基调和保持项。
- `default`（默认服装）已包含上衣时，不再重复序列化 `shirt`（上衣）字段。
- 有明确阶段服装时保留“首次出现 / 第七天”关系，不把不同时间状态当成同一镜服装。
- 不再复制长英文 Style（风格）块。
- 不把 `char_XXX` 等内部角色 ID 写进最终人物提示词正文。

### 场景提示词

- 场景资产只保留空间结构、材质与固定环境、基础光线 / 配色和视觉基调。
- 删除剧情历史，例如“某角色曾在货架旁擦咖啡机”。
- 删除“原文未明确 / 原文未说明”等分析注释。
- 删除“第七天天快亮”等单镜动态时间状态，交由分镜层按当前镜头决定。
- Story Bible（故事设定）硬事实与 Style Guide（全局视觉风格）冲突时按硬事实输出。
- 缺失静态配色产生 `W001_MISSING_COLOR`（配色信息缺失），但不让编译器自行猜色。

### 分镜提示词

- 不再输出旧版 `header / state_in / performance / focus / delta / style / continuity` 的字段式堆叠。
- 最终只选取当前镜头必要的信息：时长画幅、镜头、可见开始状态、动作与互动、场景与光线、必要约束。
- `at_window_seat`、`outerwear_changed: True`、`action_state`、`held_by`、`axis_side`、内部 ID 等不得原样进入最终 Prompt（提示词）。
- `visual_focus`（视觉重点）只影响消费信息选择和告警，不擅自重写上游景别。
- 合法上一镜连续状态可继承；不把“继续擦咖啡机 / 继续吃关东煮”等合法连续动作误判为跨镜污染。
- 下一镜动作提前进入当前镜头时产生 `E003_SPATIOTEMPORAL_POLLUTION`（跨镜污染）并阻断。

## 6. 独立审计发现的上游问题（本轮明确不越权修）

### A. Director（导演执行）存在跨镜污染

已确认至少 7 个镜头存在 Director（导演执行）把邻镜动作提前或重复写进当前镜头的情况。例如：

- SH017 提前写入 SH018 的“女人摇头”。
- SH035 提前写入 SH036 的“周迟点头”。
- SH041 提前写入 SH042 的“走到关东煮锅前、点单、说对白”。
- SH046 提前写入 SH049 的“给自己倒咖啡”。

本轮只阻断，不修改 Frozen Director（冻结导演层）。

### B. Storyboard Base（基础分镜）存在道具引用错误

已确认多个镜头的 `prop_refs`（道具引用）与画面明确操作对象不一致，例如：

- SH034：端着关东煮，但引用为纸巾。
- SH027：双手捂热水纸杯，但引用为法律援助名片。
- SH029 / SH030 / SH032：名片动作与引用错位。
- SH033：创可贴动作与引用错位。
- SH042：鱼丸是明确可见操作对象，但引用缺失。
- SH046：纸杯是当前明确可见对象，但引用缺失。
- SH049：关东煮被错误赋予“作为咖啡倒出”的状态。

这些问题属于上游数据质量，不应由最终 Prompt（提示词）层圆回来。

### C. Style Guide（全局视觉风格）与硬事实冲突

Style Guide（全局视觉风格）使用“荧光灯照明”倾向，而 Story Bible（故事设定）明确为白炽灯管。当前消费层按硬事实输出并产生 W007。更理想的长期修复位置是 Style Guide（全局视觉风格）锁定前，而不是继续堆消费层补丁。

### D. 场景配色存在 Frozen Contract（冻结契约）技术债

Story Bible（故事设定）的 `visual_lock.color` 实际保存了“原文未明确店内配色；……”这类“未知声明”。由于 PSB（场景视觉资产）规则看到同名 `visual_lock` 字段就必须 `skipped`（跳过），PSB 无法为真正缺失的店内静态配色补生产设计。

当前消费层正确做法是删除“原文未明确”并产生 W001，而不是擅自猜色。若未来要彻底解决，应显式升级上游 Story Bible / PSB 契约，而不是静默修改 v1.3 Frozen（冻结版）。

## 7. Runtime（运行时）恢复链路审计

本轮发现并修复一处新增消费层后的集成问题：重试上游 Unit（单元）时，原逻辑只清除 `compiled_project / static_evaluation`，会留下过期的 `legacy_compiled_project / consumption_evaluation / compiler_version / compile_status`。

现在任一上游重试会统一清除全部编译层物化视图和对应验证状态，再由确定性 Compile（编译）阶段重新生成。原有 input hash（输入哈希）检查点复用策略保持不变。

## 8. Frozen Core（冻结核心）审计

- 本轮新增消费层位于 `runtime/`，没有把新逻辑写回 `packages/prompt_foundry_v13`。
- Frozen Core（冻结核心）源文件继续由原 SHA（哈希）回归测试保护。
- Legacy Compiler（旧版编译器）仍保留，只用于静态安全门与 A/B（对照实验），不作为最终生成端 Prompt（提示词）。

## 10. 验收结论

本轮目标已经从“看起来更短的 Prompt（提示词）”升级为真正的消费边界：

- 正常镜头：编译成最小充分的生成指令。
- 风险镜头：输出但明确 Warning（警告）。
- 脏镜头：单镜阻断，其他镜头继续。
- 上游错误：指出来源层，不由最终编译器偷偷改剧情。
- Web（网页）：用户层中文化，工程调试信息默认折叠。
- Frozen Core（冻结核心）：保持冻结。

剩余 15 个阻断镜头是项目上游现存数据问题，不应被描述为“最终消费层已修复”。下一版若要继续提高全片可出厂率，应优先修 Storyboard Base（基础分镜）道具绑定与 Director（导演执行）跨镜证据边界，而不是继续放宽 Consumer Lint（消费层语义检查）。
