# 部署与 Strategy 发布说明

## 小程序与云端部署

1. 使用微信开发者工具导入项目根目录，确认 `miniprogramRoot` 为 `miniapp/`，上传代码并在小程序后台提交审核。
2. 在 CloudBase 控制台依次部署 `appApi`、`taskWorker`（兼容入口）和 `ttsWorker` 云函数。
3. 在 CloudRun 构建并发布 `cloudrun/gradingWorker`，然后为 `appApi` 配置 gradingWorker 的访问地址和内部令牌环境变量。
4. 访问 gradingWorker 的 `/health` 与 `/ready`；仅在 `/ready` 返回成功后提交任务。

## 公开策略产物

将开发方单独交付的下列四个文件放入运行环境约定的公开策略目录；不得替换为源码、私钥、明文 Prompt 或环境变量：

- `public-contract.json`
- `strategy-public.envelope.json`
- `strategy-manifest.json`
- `strategy-signing-public.pem`

启用前必须验证四个文件齐全、manifest 文件哈希、签名、artifactHash、策略版本、最低客户端契约版本，以及 `output-schema-registry.v1`、`result-semantics.v1`、`model-runtime.v1` 和 `model-output-repair.v1`。验证失败时保持上一份已验证策略，不得启用未验证文件。

## 必要环境变量

按现有部署模板配置 CloudBase 环境、Ark 访问参数、gradingWorker 内部令牌、策略服务地址和策略授权参数。仅填写客户自己的值；不得提交 Ark Key、TTS Key、私钥或开发方密钥到源码。

## 验收步骤

分别创建难题、阅读三格法、计算马虎各一条脱敏测试任务。仅当 `task.status` 为 `COMPLETED` 且存在 `resultId` 时进入结果页。若失败，检查任务的安全错误码，例如 `ARK_REQUEST_TIMEOUT`、`ARK_OUTPUT_TRUNCATED`、`LLM_SCHEMA_ERROR`。

## 回滚

公开策略验证或替换失败时保留上一份已验证版本。需要人工回滚时，恢复上一份已验证公开产物并重新执行 hash 与签名验证。

## 微信开发者工具编译

本机未发现微信开发者工具 CLI。请在微信开发者工具中导入项目后执行“编译”，再进行真机预览和上传；不需要新增 `miniprogram-ci` 依赖。
