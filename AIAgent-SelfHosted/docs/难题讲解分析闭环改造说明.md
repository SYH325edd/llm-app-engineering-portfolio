# 难题训练“解题过程与讲解分析”闭环改造说明

## 1. 改造范围

本次仅改造 `HARD_PROBLEM_CHECK`，继续使用 `hard-problem.v2`。未新增训练模式，未修改任务创建、图片上传、数据库集合、打卡阈值和错题集合结构。

以下内容保持原样：

- `CARELESS_TRAINING + READING` 审题马虎训练；
- `CARELESS_TRAINING + CALCULATION` 计算马虎训练；
- 两类马虎训练的 Prompt、结果结构、页面和 TTS。

## 2. 支持的图片结构

系统先识别题目区，再识别学生作答区。学生作答区兼容：

1. 左右对应：左侧解题过程，右侧对应讲解；
2. 上下分段：上方算式或过程，下方编号讲解；
3. 横线分块：每个横线区间是一组过程与讲解；
4. 混合版式：综合使用编号、空间位置、分隔线、阅读顺序和语义配对。

图片版式只用于内部解析，不进入业务结果。

## 3. 唯一数据契约

每道 `hard-problem.v2` 题目新增两个必填字段：

- `stepFeedbacks`：逐步过程与讲解分析；
- `overallFeedback`：整题综合反馈。

`stepFeedbacks[]` 必须包含：

- `stepIndex`
- `solutionText`
- `explanationText`
- `solutionStatus`
- `explanationStatus`
- `logicStatus`
- `analysis`
- `correctionAdvice`

固定枚举：

- `solutionStatus`: `correct | wrong | missing | unreadable`
- `explanationStatus`: `clear | partially_clear | incorrect | missing | unreadable`
- `logicStatus`: `clear | insufficient | wrong | unreadable`

学生原文只进入 `studentAnswer`、`solutionText`、`explanationText`；AI判断和建议只进入状态、`analysis`、`correctionAdvice`、`overallFeedback`，不得互相污染。

## 4. 完整数据链路

```text
图片输入
→ 1.3.15 hardProblem Prompt
→ PRIMARY 完整结构化输出
→ hard-problem.v2 Schema 与嵌套字段校验
→ REVIEW 按相同契约独立复核
→ 按 sourceKey 合并并重新校验
→ 原有 results 结果落库与 API 返回
→ 难题结果页逐步展示
→ TTS 按同一结果逐步朗读
```

前端和 TTS 不重新判断，只消费落库后的同一结构化结果。

## 5. 兼容策略

- 新策略版本：`1.3.15`；
- 历史 `hard-problem.v2` 记录没有 `stepFeedbacks` 时，结果页和 TTS继续走原有展示与朗读回退；
- 加密内嵌策略仍是旧版兜底，不包含本次 Prompt。正式使用本功能时必须部署当前工程中的 `strategyService`，并确保运行环境能够读取对应正式策略；
- 旧内嵌策略被使用时，运行时兼容逻辑不会强制要求新字段，因此不会导致旧兜底直接崩溃，但也不会产生新的逐步分析结果。

## 6. 部署顺序

1. 部署当前工程中的 `cloudfunctions/strategyService`，确认策略源与发布清单版本一致；
2. 从当前唯一源码工程部署 `taskWorker`、`appApi`、`ttsWorker` 及现有 CloudRun gradingWorker；
3. 重新部署或重启相关运行实例，使内存策略缓存重新加载；
4. 确认策略服务返回版本为 `1.3.15`；
5. 使用真实图片分别验证左右型、上下/横线型、讲解缺失型。

## 7. 验证结果

- Strategy 测试：50/50 通过；
- Runtime 非联网测试：328/328 通过；
- Docker 构建上下文测试中的 `npm ci` 因当前执行环境的内部 npm 镜像缺少 `ws@8.21.1` 而无法完成；原始未修改上传包在同一环境中也出现相同 404，属于外部依赖环境问题，不是本次改造引入的失败；该测试其余两个本地检查通过。
